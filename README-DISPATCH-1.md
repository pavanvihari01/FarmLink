## What actually changed

### 1. Duplicate SQLite database bug — fixed

`config.py` previously defaulted to `sqlite:///./farmlink.db`. That relative
path resolved against the shell's working directory, so running uvicorn from
`FarmLink\` created `FarmLink\farmlink.db`, while running it from
`FarmLink\backend\` created `FarmLink\backend\farmlink.db`. Two databases,
different data, identical app.

The default is now an absolute path anchored to the config file's location:

    BACKEND_ROOT = Path(__file__).resolve().parents[2]   # -> backend/
    DEFAULT_SQLITE_URL = f"sqlite:///{(BACKEND_ROOT / 'farmlink.db').as_posix()}"

`backend/farmlink.db` is now the canonical local database, regardless of where
you launch from. The old `FarmLink/farmlink.db` is untouched.

`config.py` also now anchors `env_file` to `backend/.env`, so `.env` is picked
up whether you run from the project root or from `backend/`.

### 2. Alembic added

- `alembic.ini` at `backend/` with `script_location = migrations`.
- `migrations/env.py` reads the URL from `get_settings()` — one source of truth
  for `.env`, real environment variables, and the SQLite default.
- `migrations/versions/0001_initial_schema.py` is a hand-written initial
  revision matching `app/models/entities.py`: `users`, `categories`,
  `listings`, `orders`, including the unique index on `users.email` and
  server-side defaults for boolean and string columns.
- `render_as_batch=True` so future SQLite `ALTER` operations work.

### 3. Startup no longer blanket-creates tables

`main.py` now branches:

    if settings.database_url.startswith('sqlite'):
        Base.metadata.create_all(bind=engine)

PostgreSQL is migration-driven. Running `alembic upgrade head` is a required
setup step before first boot against Postgres.

### 4. Seeding gated behind `DEMO_MODE`

    if settings.demo_mode:
        db = SessionLocal()
        try:
            seed(db)
        finally:
            db.close()

`seed()` itself still no-ops on a non-empty database. Setting `DEMO_MODE=false`
means a real database never receives demo rows.

## Optional cleanup (not performed by this archive)

`FarmLink/farmlink.db` may be a stale duplicate. Do not delete it until you
have confirmed which database contains data you want. Once verified:

    Get-Item E:\myApps\Project\FarmLink\farmlink.db |
        Move-Item -Destination E:\myApps\Project\FarmLink\farmlink.db.bak

Renaming is preferred over deleting: it is reversible, and it frees the path
if any stale script still writes there.

## Known limitations of this dispatch

- The initial migration is hand-written, not autogenerated. It matches
  `entities.py` exactly as read during investigation, but if you have made
  local schema edits since, run `alembic revision --autogenerate` against your
  actual database and diff the result before applying.
- Existing SQLite databases created by `create_all()` do not have an
  `alembic_version` table. Use `alembic stamp head` to mark them as current
  rather than replaying `0001_initial` (which would fail on existing tables).
- No `alembic upgrade head` is run automatically at startup. That is
  deliberate: schema changes should never be a side effect of starting a web
  process.
